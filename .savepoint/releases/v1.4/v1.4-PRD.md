# Release v1.4 - Audit Register and TUI Review

## Overview

v1.4 adds a repo-wide Audit Register so Savepoint audits can converge over time instead of restarting from a cold scan. Findings get stable IDs, audit runs are recorded as history, closure requires named proof, and the board gains a read-only Audit section for reviewing the reusable prompt, current findings, and run history.

Savepoint remains file-first and agent-agnostic. The register is durable markdown project state under `.savepoint/audit/`; the TUI reviews that state but does not edit finding lifecycle fields in this release.

## Product rules

- Audit register storage is repo-wide at `.savepoint/audit/`.
- Findings may reference releases, epics, tasks, defects, source locations, and guardrail IDs.
- Finding IDs are stable across audit runs.
- Audit run files are append-only historical evidence.
- The register is the mutable current state derived from runs and user/agent disposition work.
- Reconciliation is manual and agent-guided in v1.4; Savepoint does not automatically merge findings by signature.
- A finding reaches `verified` only when it has named proof, preferably a passing regression test or an explicit manual verification note.
- Waivers and owner decisions are recorded in markdown; the TUI does not create or approve them.
- The board Audit section is read-only in v1.4.
- Missing audit files render recoverable empty states rather than blocking the board.
- Existing defect and release-doc shortcuts stay unchanged: `d` remains defects and `D` remains docs.
- `A` opens the Audit Register overlay.

## Audit file layout

`.savepoint/audit/`:

- `prompt.md` - canonical reusable audit prompt with changelog
- `register.md` - current finding index and convergence summary
- `findings/` - durable finding records named `F###-slug.md`
- `runs/` - immutable audit run records named `YYYY-MM-DD-label.md`

## Finding lifecycle

Supported statuses:

- `open`
- `triaged`
- `mapped`
- `in_progress`
- `fixed`
- `verified`
- `deferred`
- `owner_decision`
- `waived`
- `duplicate`

Each finding records severity, confidence, linked work item, guardrail IDs, source locations, proof needed, first seen, last seen, and optional duplicate/defer/waiver metadata.

## TUI behavior

- `A` opens the Audit Register overlay.
- `[` and `]` switch tabs.
- Prompt tab renders `.savepoint/audit/prompt.md`.
- Findings tab lists findings grouped by status and severity.
- `enter` on a finding opens read-only finding detail.
- Runs tab lists run history and summary counts.
- `esc` and `q` close the overlay or return from detail to the finding list.
- `up`/`down`, `k`/`j`, `pgup`, and `pgdown` scroll lists and detail bodies.
- Epic detail and task detail show a read-only linked-findings section; `enter` on a linked finding opens the finding detail and `esc` returns to the work-item detail.

## Success criteria

- A new Savepoint project includes audit-register documentation assets without changing the existing workflow.
- Existing projects can receive audit-register assets through upgrade-assets without overwriting user-edited audit files.
- Audit finding and run records parse into typed data with actionable validation errors.
- `savepoint doctor` reports malformed audit-register state without blocking projects that have no audit register yet.
- The board opens the Audit Register overlay with `A` and renders prompt, findings, runs, details, and empty states.
- Epic detail and task detail surface findings linked to that work item and drill into the read-only finding detail.
- The TUI remains read-only for audit state in v1.4.
- Existing board navigation, defects, and release docs behavior remain unchanged; epic and task detail gain only the read-only linked-findings section.
- Manual reconciliation guidance is clear enough for an agent to preserve stable finding IDs across runs.

## Out of scope

- Editing audit findings from the TUI
- CLI commands for registering runs or changing finding status
- Automatic finding matching or signature-based merge decisions
- External tracker sync
- Dashboards or charts
- Auto-generated fixes
- Launching audit agents
- Replacing release-level `E##-Audit.md` files
