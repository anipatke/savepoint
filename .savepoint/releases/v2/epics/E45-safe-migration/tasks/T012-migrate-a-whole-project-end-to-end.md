# T012: Migrate a whole project end to end

## Problem

Every preceding task proves its own piece. None of them proves the thing the epic actually promises: that a real V1 project, converted through the real command, becomes a V2 project that loads without a diagnostic and has lost nothing.

That gap is where migration bugs live. A record can render correctly and still reference an ID that another task allocated differently. An archive can be byte-perfect and still miss a file that classification never reported. A second run can be idempotent per-file and still churn a modification time somewhere. These only show up when the whole thing runs against the fixtures E41 froze for exactly this purpose.

This is also where the epic's honesty claims get their last check: nothing in the migrated project should carry clearance, and every legacy fact that could not become a V2 record should be resolvable through the manifest.

## Acceptance Criteria

- [ ] Both frozen fixtures are copied to temporary directories and migrated through the real command path; no test mutates a fixture in place, and no live project is used, satisfying TEST-04.
- [ ] Each migrated project loads through `LoadV2Index` with no diagnostic.
- [ ] Every reference resolves: each Task's `objective`, each `depends_on` target, each Issue's `tasks` and `checks`, each `duplicate_of`, and each Objective's `depends_on`.
- [ ] No converted record carries clearance the source did not record, and a test asserts a converted active Task is not completable under E43's gates because its clearance is unknown.
- [ ] Every file named in each fixture's `manifest.yml` has an accountable destination — converted, preserved in place, or archived — and a test enumerates the manifest and fails naming any file with none.
- [ ] Every archived file hashes equal to the SHA-256 its fixture manifest records, with the manifest read as the expectation rather than regenerated.
- [ ] `v1-history`'s recurring `E01-example/T001-shared` appears as two distinct Tasks with distinct global IDs, and the manifest records which release each came from.
- [ ] Legacy facts that have no V2 record — completed Tasks, verified and waived findings, legacy prerequisites — are all resolvable through `v1-to-v2.yml`.
- [ ] Golden files capture each fixture's converted output under an injected fixed clock and operation ID, and a rerun reproduces them byte for byte; a golden mismatch is reported as a behavior change rather than being regenerated by the test.
- [ ] A second full run over each migrated project changes no file content, no modification time, and no ID.
- [ ] Preview over both fixtures writes nothing, asserted by a bytes-and-mtimes snapshot across the command.
- [ ] `v1-basic`, which has no `audit/`, no `Health-Check.md`, and no `AGENTS.md`, migrates with no finding for any of those absences.
- [ ] The epic's quality-gate outcomes are recorded by name in the Context Log: the named test cases, their results, and any limitation the evidence does not cover.
