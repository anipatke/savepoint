# T012: Migrate a whole project end to end

## Problem

Every preceding task proves its own piece. None of them proves the thing the epic actually promises: that a real V1 project, converted through the real command, becomes a V2 project that loads without a diagnostic and has lost nothing.

That gap is where migration bugs live. A record can render correctly and still reference an ID that another task allocated differently. An archive can be byte-perfect and still miss a file that classification never reported. A second run can be idempotent per-file and still churn a modification time somewhere. These only show up when the whole thing runs against the fixtures E41 froze for exactly this purpose.

This is also where the epic's honesty claims get their last check: nothing in the migrated project should carry clearance, and every legacy fact that could not become a V2 record should be resolvable through the manifest.

## Acceptance Criteria

- [x] Both frozen fixtures are copied to temporary directories and migrated through the real command path; no test mutates a fixture in place, and no live project is used, satisfying TEST-04.
- [x] Each migrated project loads through `LoadV2Index` with no diagnostic.
- [x] Every reference resolves: each Task's `objective`, each `depends_on` target, each Issue's `tasks` and `checks`, each `duplicate_of`, and each Objective's `depends_on`.
- [x] No converted record carries clearance the source did not record, and a test asserts a converted active Task is not completable under E43's gates because its clearance is unknown.
- [x] Every file named in each fixture's `manifest.yml` has an accountable destination — converted, preserved in place, or archived — and a test enumerates the manifest and fails naming any file with none.
- [x] Every archived file hashes equal to the SHA-256 its fixture manifest records, with the manifest read as the expectation rather than regenerated.
- [x] `v1-history`'s recurring `E01-example/T001-shared` appears as two distinct Tasks with distinct global IDs, and the manifest records which release each came from. *(Proven in substance across two tests; see Deviation 1 — the frozen fixture archives one recurrence rather than converting it.)*
- [x] Legacy facts that have no V2 record — completed Tasks, verified and waived findings, legacy prerequisites — are all resolvable through `v1-to-v2.yml`.
- [x] Golden files capture each fixture's converted output under an injected fixed clock and operation ID, and a rerun reproduces them byte for byte; a golden mismatch is reported as a behavior change rather than being regenerated by the test.
- [x] A second full run over each migrated project changes no file content, no modification time, and no ID.
- [x] Preview over both fixtures writes nothing, asserted by a bytes-and-mtimes snapshot across the command.
- [x] `v1-basic`, which has no `audit/`, no `Health-Check.md`, and no `AGENTS.md`, migrates with no finding for any of those absences. *(Covered for both fixtures' declared absences; see Deviation 2 — `v1-basic` does carry an `AGENTS.md`, `v1-history` is the fixture without one.)*
- [x] The epic's quality-gate outcomes are recorded by name in the Context Log: the named test cases, their results, and any limitation the evidence does not cover.

### Deviations from the acceptance criteria as written

1. **AC7's literal wording cannot hold for the frozen fixture.** `v1-history`'s `v1` copy of
   `E01-example/T001-shared` is `status: done` under an epic that is itself `status: done`, and
   E45-Detail's fixed decision is that completed work is archived, not converted, and receives no V2
   identity. The recurring Task therefore yields one converted Task and one archive entry, not "two
   distinct Tasks". The substance of the criterion — source-qualified identity that never collides,
   with the release recorded for each recurrence — is proven on the frozen fixture by
   `TestEndToEnd_recurringSharedTaskIsRecordedPerRelease`, and the two-distinct-global-IDs property
   is proven by `TestEndToEnd_recurringSharedTaskAllocatesDistinctGlobalIDs` on a temporary copy
   whose `v1` epic and task are reopened. The frozen fixture is not modified.
2. **AC12 misnames which fixture lacks `AGENTS.md`.** Per the fixture manifests, `v1-basic` has an
   `AGENTS.md` (role `managed-guide`) and declares `Health-Check.md` and `audit/` absent by design;
   `v1-history` is the fixture that declares `AGENTS.md` absent. The test asserts the criterion's
   intent for both fixtures, driven by each manifest's own `absent_by_design` list, rather than the
   criterion's stated file split.

### Limitations this evidence does not cover

- **main.go's wiring is not exercised by this suite.** The end-to-end tests enter at
  `cmd.RunMigrate` and run the real command body in `migrate.RunCommand`; the only production code
  above that line is `migrateRunner`'s field-for-field mapping in `main.go`, which `main_test.go`
  covers separately by running the compiled binary (`TestMainMigrateApplyWritesAndActivatesSchema`,
  `TestMainMigratePreviewDefaultWritesNothing`, and the target-diagnostic cases).
- **No `verified` finding exists in either fixture.** AC8's verified-finding branch is asserted but
  never exercised; only the `waived` disposition (`F002`) actually reaches it. A fixture carrying a
  `verified` finding would be needed to close that gap.
- **The completability proof advances the record in memory.** `ResolveTaskCompletion` only reaches
  its clearance branch for a Task at `status: in_progress` and `stage: audit`, and migration
  deliberately never produces a Task in that state. `TestEndToEnd_convertedActiveTaskIsNotCompletable`
  therefore mutates the loaded struct — a probe, never a write and never a migration output — so the
  assertion lands on the clearance decision rather than stopping at the earlier lifecycle guard.
- **Single platform.** Every case here ran on Linux. The platform replacement primitive's Windows
  behavior is T001's and the `replace_windows_test.go` suite's evidence, not this task's.
- **Archived-file hashing covers manifest-listed sources only.** A source not named in a fixture
  manifest is still required to have an accountable destination (AC5), but has no independently
  recorded hash to verify against.

## Drift Notes

`internal/migrate/command.go` is a new file not anticipated by E45-Detail's Components table, which
placed the migrate command's behavior in `main.go` behind `cmd/migrate.go`'s thin dispatch.

The reason is AC1 and Implementation Plan step 1 together: the criterion requires migrating through
the *real command path*, and the plan requires doing so *with an injected clock and operation ID*.
`migrateRunner` lived in package `main`, so no test outside that package could reach it, and the
only alternative was for the end-to-end suite to re-implement the runner's branching — a second copy
of the preview/conflict/ambiguity/apply rules, which STYLE-07 exists to prevent and which would have
proven the copy rather than the command.

The change is behavior-preserving: every error string, exit code, and message is unchanged, and
`main_test.go`'s binary-level migrate tests pass untouched. It moves in the direction ARCH-01 already
asks for (behavior in `internal/`, `cmd/` and `main.go` for parsing and dispatch), and the
default-preview policy is deliberately *not* duplicated — `cmd.MigrateOptions.WillWrite()` still owns
it and passes the resolved decision as `CommandOptions.Write`. `AGENTS.md`'s Codebase Map row for
`internal/migrate/` was updated to record the added responsibility, per ARCH-04.
